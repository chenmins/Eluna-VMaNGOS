# 范围自动拾取功能设计文档

## 概述

范围自动拾取（AoE Loot）功能通过自动合并附近多个尸体的战利品到单个拾取窗口来增强拾取体验。此功能对于快速连续击杀多个敌人的玩家特别有用，因为它消除了逐个拾取每个尸体的需要。

## 功能说明

当玩家打开生物尸体的拾取窗口时，系统会自动搜索可配置范围内的其他可拾取尸体，并将它们的战利品合并到主拾取窗口中。这允许玩家通过单次拾取操作从多次击杀中收集战利品。

### 主要优势

1. **改善玩家体验**：减少逐个拾取多个尸体的繁琐任务
2. **时间效率**：加快 AoE 刷怪场景的拾取过程
3. **可配置**：服务器管理员可以根据自己的偏好自定义功能
4. **性能考虑**：包括限制以防止性能下降

## 配置选项

所有配置选项都添加到 `mangosd.conf` 中，并具有合理的默认值：

### AoELoot.Enable
- **描述**：启用或禁用 AoE 拾取功能的主开关
- **默认值**：1（启用）
- **可选值**：0（禁用），1（启用）

### AoELoot.Message
- **描述**：玩家登录时显示有关 AoE 拾取功能的消息
- **默认值**：1（启用）
- **可选值**：0（禁用），1（启用）
- **注意**：当前需要在玩家登录处理程序中实现消息显示逻辑

### AoELoot.Range
- **描述**：搜索附近可拾取尸体的最大范围（码）
- **默认值**：55.0
- **有效范围**：5.0 - 100.0（自动限制）
- **注意**：更大的范围增加搜索半径，但可能影响性能

### AoELoot.Group
- **描述**：控制玩家在组队时 AoE 拾取是否工作
- **默认值**：1（启用）
- **可选值**：
  - 0（禁用 - AoE 拾取仅在单人时工作）
  - 1（启用 - AoE 拾取在组队时也工作）

### AoELoot.MaxCorpses
- **描述**：合并到拾取窗口的最大附近尸体数量
- **默认值**：10
- **有效范围**：1 - 20（自动限制）
- **注意**：较低的值改善性能；较高的值允许一次拾取更多尸体

## 技术实现

### 架构

实现包括以下组件：

#### 1. 配置文件
- `conf/aoe_loot.conf.dist` - 带详细文档的独立配置文件
- `src/mangosd/mangosd.conf.dist.in` - 将 AoE 拾取设置集成到主配置中

#### 2. 核心实现
位置：`src/game/Handlers/LootHandler.cpp`

**组件：**

##### 辅助类：`MaNGOS::AllLootableDeadCreaturesInRange`
网格通知检查类，识别范围内可拾取的死亡生物。它验证：
- 生物未存活
- 生物在指定范围内
- 生物设置了 LOOTABLE 标志
- 生物有拾取接收者
- 玩家有权限拾取（是接收者或在同一组中）

##### 辅助函数：`GetNearbyLootableCorpses()`
使用 Cell 访问者模式搜索网格中附近可拾取的尸体：
```cpp
static void GetNearbyLootableCorpses(
    std::list<Creature*>& corpseList,
    Player* player,
    Creature* excludeCreature,
    float range)
```

##### 修改的函数：`WorldSession::HandleLootOpcode()`
增强以包含 AoE 拾取逻辑：
1. 执行所有标准拾取检查
2. 如果启用了 AoE 拾取且目标是生物：
   - 读取配置设置
   - 搜索附近可拾取的尸体
   - 合并找到的尸体的战利品：
     - 组合金币数量（带溢出保护）
     - 复制物品（遵守 MAX_NR_LOOT_ITEMS 限制）
   - 创建临时合并视图；源尸体在玩家实际拿取物品或金币前保持不变
3. 向玩家发送合并的拾取窗口

### 战利品合并过程

1. **目标选择**：玩家对生物尸体发起拾取
2. **验证**：系统验证 AoE 拾取是否启用以及条件是否满足
3. **搜索**：系统在配置范围内搜索附近可拾取的尸体
4. **权限检查**：验证每个尸体的拾取权限
5. **合并**：
   - 金币数量求和（带溢出保护）
   - 物品复制到主拾取窗口（直到物品限制）
   - 关闭且未拾取时，撤销临时合并并保留源尸体
   - 成功拿取任一物品或金币后，才清除源尸体并提交合并结果
6. **显示**：向玩家显示合并的拾取窗口

### 安全功能

1. **范围限制**：拾取范围自动限制在 5.0 到 100.0 码之间
2. **尸体限制**：处理的最大尸体数限制在 1 到 20 之间
3. **溢出保护**：金币合并包括检查以防止 uint32 溢出
4. **物品限制**：遵守游戏的 MAX_NR_LOOT_ITEMS（16）限制
5. **权限检查**：仅拾取玩家有权限拾取的尸体
6. **组队支持切换**：如果需要，可以在组队场景中禁用

### 性能考虑

1. **有限搜索半径**：默认 55 码范围平衡了可用性和性能
2. **尸体数量限制**：默认 10 个尸体防止过度处理
3. **早期终止**：达到物品限制时停止处理
4. **高效网格搜索**：使用 MaNGOS Cell 访问者模式进行最佳网格遍历

## 兼容性

### 客户端版本
该功能适用于所有支持的客户端版本，因为它在服务器端运行，无需客户端修改。

### 组队拾取模式
与所有组队拾取模式兼容：
- 自由拾取
- 轮流拾取
- 队长分配
- 组队拾取
- 需求优先

该功能遵守现有的拾取权限，仅合并玩家可以合法拾取的尸体。

## 未来增强

未来版本的潜在改进：

1. **登录消息实现**：玩家登录时添加实际消息显示
2. **个人切换**：允许玩家通过命令启用/禁用 AoE 拾取
3. **拾取优先级**：合并拾取的智能排序（例如，任务物品优先）
4. **视觉反馈**：可选的 UI 指示器显示拾取的尸体数量
5. **统计跟踪**：记录 AoE 拾取使用情况用于服务器分析
6. **基于距离的排序**：优先拾取较近的尸体
